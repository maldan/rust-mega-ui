# Критичные недочёты mega-ui

Не про коммиты, размеры файлов и то, что код пишет агент.

## 1. Node graph: unsafe с алиасингом и висячим указателем

В `node()` берётся `&mut NodeSpace` через `NonNull`, и этот borrow живёт через `add(self)`.
Внутри `add` снова вызывается `node_port()`, который делает второй `as_mut()` на тот же
указатель, пока первый `space` ещё в скоупе.

Это классический aliasing UB. Miri это поймает. Сейчас «работает, потому что LLVM
пока не соптимизировал».

Плюс указатель кладётся в `Ui` и снимается только в конце `node_space_rect`.
`begin_frame` его не обнуляет. Паника внутри графа → следующий кадр может дернуть
`node()` по dangling pointer.

**Что сделать:** не хранить raw pointer. Либо `Ui` временно отдаёт `&mut NodeSpace` через
стек с Drop-гардом (обнуление при unwind), либо порты/ноды принимают
`space: &mut NodeSpace` явно. Внутри одной функции — не держать `space` живым через
вызовы, которые сами берут тот же pointer.

## 2. Конструктор библиотеки паникует из‑за шрифта

`Ui::new()` → `Font::load_default()` → жёсткий список путей (Segoe/Arial/DejaVu) → `panic!`.

На Linux без пакета шрифтов, в Docker, CI, кастомном Windows — библиотека не стартует.
Шрифт с диска ещё и не эмбеддится, fallback-фейсов нет.

**Что сделать:** бандл одного TTF в crate (даже крошечный), `Result`/`Option` на загрузку,
fallback на встроенный. Пути ОС — как дополнение, не как единственный способ жить.

## 3. Retained-состояние виджетов никогда не чистится

`win_rects` прунятся. Остальное нет: `scrolls`, `edits`, `headers`, `trees`, `selects`, `windows`,
`tabs`, `button_sizes`, `group_sizes`, `curve_edits`, `num_bufs`, …

Immediate-mode так и задуман, но без generation/GC это:

- утечка в долгих сессиях (динамические id, деревья, ноды);
- зомби-стейт, если тот же id переиспользуется для другого виджета.

**Что сделать:** как в Dear ImGui / egui — `last_used_frame` и раз в N кадров `retain`.
Это сильно поднимает «можно жить в редакторе часами».

## 4. Идентичность виджетов хрупкая — источник самых злых багов

- `Id` = `DefaultHasher` (алгоритм не стабилен по контракту std).
- Кнопка: id = текст лейбла. Две «OK» в одном скоупе делят hover/active.
- Окно: id = title. Два окна с одним заголовком — одна позиция/фокус.
- Нет debug-детекта коллизий (у ImGui это must-have).

Без `id_scope` / уникальных id хост молча получает «кликнул одно, сработало другое».
Для библиотеки это хуже, чем кривой цвет.

**Что сделать:** `button_with_id`, отдельный `Window::id`, в debug — карта `Id → source path`
и assert на коллизию. Hasher с фиксированными ключами (fxhash/ahash), не «какой
получится DefaultHasher».

## 5. Текст не тянет продукт

- `key_delete` в инпуте есть, в `text_input` / `text_area` не обрабатывается (только Backspace).
  Delete работает в графе/кривых, в полях — нет.
- Нет IME (CJK, составные символы).
- Один face, нет fallback. Кириллица ок, если глиф в том же TTF; CJK/emoji — пусто или tofu.
- Атлас 1024×1024, overflow → сброс на следующий кадр, глифы пропадают на кадр.

Для тулкита редактора это потолок качества текста. Починка Delete — мелочь.
Эмбед + fallback + чуть больший/мульти-атлас — уже другой класс.

## 6. Тема закрыта наглухо

`theme` — `pub(crate)`, один deep-dark. Хост не может сделать светлую тему, бренд,
контраст, high-DPI spacing отдельно от цвета.

Пока это «демо-скин внутри либы». Публичный `Style` (цвета + радиусы + размеры)
сразу делает crate пригодным чужим приложениям, без форка.

## 7. Рендер молча отрезает UI

`MAX_QUADS = 50_000`, `take(MAX_QUADS)`. Сетка нод-графа рисует по линии на квад.
Большой zoom-out → часть UI просто не рисуется, без флага в `DrawStats`/лога.

Для графа это не теоретический лимит. Либо инстансинг сетки / один SDF-квад на фон,
либо растущий буфер и явный `clipped: true` в статах.

## 8. Почти нет тестов на сам UI

Юниты есть у dock-геометрии, кривых, edit-байт-оффсетов, node-space логики.
Нет кадра: `begin_frame` → виджет → клик → `clicked` / фокус / id-коллизия / clip.

При этом mismatch слоёв — это `unwrap()` на пустом стеке. Хост ошибётся в layout —
паника посреди кадра, не понятное сообщение.

**Что сделать:** тестовый headless кадр (`UiInput` без wgpu) на button/window/text_input/scroll.
`debug_assert` с «unclosed group/scroll» вместо голого unwrap.

## 9. Горячий путь графа — аллокации на каждый линк

Хиты и отрисовка линков каждый кадр делают `from_node.clone()` + `from_port.clone()`
как ключ `HashMap`. Строковые id везде.

На сотнях нод это будет лагать раньше GPU. Interned `NodeId`/`PortId` (`u32`) и ключ
без clone — большой выигрыш именно в той фиче, которой либа выделяется.

## Не критично

Не чинить ради «качества либы»:

- одинаковые коммиты;
- размеры файлов;
- god-object `Ui` как эстетика;
- отсутствие Tab-фокуса (у imgui так и живут);
- dock без tear-off (это фича, не дыра в текущем контракте).

## ROI

Если чинить по отдаче:

1. убрать UB в графе + Drop-гард указателя
2. встроенный шрифт
3. GC стейта + жесткие id
4. Delete / тема / `MAX_QUADS`

Это уже другой уровень надёжности, без переписывания всех виджетов.
